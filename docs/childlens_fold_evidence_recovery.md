# ChildLens fold-evidence recovery amendment

This amendment preserves the historical `NO_GO_MEDIA_GROUNDING_ENV` and
`NO_GO_ADAPTIVE_MEDIA_REPAIR` records unchanged. It authorizes only recovery of
the exact clean V5 development package and the already-frozen cross-fit
readiness procedure. It does not authorize a cue-lift arm.

The external volume was inventoried without decoding media. A read-only mounted
disk image named `ChildLensRestricted.sparsebundle` contained the complete V5
package. All five restricted artifact hashes match the clean validation
receipt. The package attests clean run `childlens-v5-clean-20260723-a`, 18
development participants, zero locked participants, 58 sources, and three
six-participant folds. It was restored outside Git to the original hidden,
owner-only private namespace with `.metadata_never_index`.

The original deterministic summary routine was run over the restored selection,
annotations, feature manifest, and frontend features. Its canonical output was
byte-identical to the committed pooled summary. No tolerance rule was needed.

Blender 4.2.1 LTS was replayed twice from the committed adapter. Physical state
and MP4 hashes were byte-identical to each other and to the earlier engineering
receipt; all contact, joint, IMU, static-control, and playable-media gates
passed.

Cross-fit calibration cannot pass with the current adapter. It exposes one
fixed 0.5-second episode specification, not an episode-distribution generator.
Repeated runs are byte-identical and therefore provide zero independent support
for speech timing, activity recurrence, candidate-event density, motion,
scene-change, persistence, or waveform distribution shape. Counting identical
replays as separate assessment episodes would be pseudoreplication. Generator
selection and assessment scoring were therefore stopped before readiness
controls. No oracle, destroyed-mapping, learner outcome, or cue-lift treatment
was run.

**Decision: `NO_GO_CROSSFIT_MEDIA_CALIBRATION`.**
